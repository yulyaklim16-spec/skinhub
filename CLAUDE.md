## 1. Суть продукта

**SkinHub** — геймифицированная веб-платформа вокруг скинов Counter-Strike 2: открытие кейсов,
апгрейды, баттлы и мета-прогрессия (уровни, миссии, сезоны).

**Задача:** сделать продукт с самым простым и понятным интерфейсом в категории и с более высокой
конверсией и удержанием, чем у конкурентов.

**Рынок и конкуренты:** Casehug, Hellcase, Skin.club (лучшие примеры), Rain.gg, Forcedrop,
JamSkins, Upgrader.pro (худшие). Разбор в [`research/research.md`](./research/research.md).

## 2. Аудитория

Игроки CS2 от 18 лет, которые интересуются скинами. Значительная доля заходит с телефона.
Ключевые боли из исследования: непонятно, с чего начать; нельзя попробовать без регистрации;
нет доверия к честности выпадения.

## 3. Принципы продукта

Выведены из исследования, источник в скобках.

1. **Попробовать до входа.** Демо-открытие любого кейса без регистрации, с пометкой «выигрыш не
   засчитывается». Вход через Steam или Google только при реальной ставке. *(Forcedrop, JamSkins)*
2. **Первый экран продаёт ивент.** Живая лента дропов над шапкой, герой ивента на весь экран
   с таймером и переходом в ивент. Каталог кейсов с ценами сразу под первым экраном.
   *(Casehug, Skin.club; решение владельца 2026-10-02, см. `wireframes/home.md`)*
3. **Прогресс на кнопке.** Каждое действие показывает, сколько XP и ивент-валюты оно даст.
   *(Casehug)*
4. **Ежедневная петля.** Миссии со счётчиком, бесплатный кейс по уровню, сезоны раз в 3–4 недели.
   *(Skin.club, Hellcase)*
5. **Честность как интерфейс.** Provably Fair на каждом открытии, шансы предметов в процентах,
   сроки вывода на виду.
6. **Одна строка режимов.** Кейсы, Баттлы, Апгрейд, Контракты, Ивент. Новые режимы открываются
   по уровню.

**Делаем (решение 2026-10-02):** ленту дропов над шапкой, героя ивента на весь экран, таймеры
офферов и ивентов, поле промокода на главной.

**Не делаем:** статистику и соцсети в шапке, несколько горизонтальных навигаций, регистрацию
как главный блок первого экрана, главную на десятки тысяч пикселей, чат постоянной колонкой,
неон и много акцентных цветов.

## 4. Ограничения

- **Юридические.** Платное открытие кейсов во многих странах регулируется как азартная игра.
  Гео-ограничения, проверка возраста 18+ и лицензия закладываются в дизайн с самого начала
  (экраны верификации, блокировка по региону, ответственная игра).
- **Платформа.** Адаптивный веб, mobile-first.
- **Валюта.** Все цены, баланс и выигрыши в долларах США, без внутренней валюты (решение 2026-10-02).
- **Состав v1.** Режимы Cases, Battles, Upgrade, Contracts (с 5 уровня), Event; чат (плавающая кнопка,
  панель поверх страницы) — решение 2026-10-02.
- **Steam.** Вход и вывод скинов через Steam (трейд-оффер), это задаёт сценарии вывода.

## 5. Структура репозитория

| Папка | Что внутри |
|---|---|
| `research/` | Исследование: `research.md`, `research.html`, скриншоты в `screens/` |
| `wireframes/` | Вайрфреймы: по паре `<экран>.md` / `<экран>.html` на экран (`home`, `case`, …) |
| `concept/` | Визуальный концепт: мудборды, направления, ключевые экраны |
| `tokens/` | Дизайн-токены: цвет, типографика, отступы, радиусы |
| `components/` | Спецификации компонентов |
| `design-system/` | Собранная дизайн-система и гайдлайны |
| `handoff/` | Передача в разработку: спецификации экранов, ассеты, состояния |

Порядок этапов: research → wireframes → concept → tokens → components → design-system → handoff.

## 6. Рабочие соглашения

1. **MD для Claude, HTML для человека.** У каждого артефакта два формата.
   `.md` — рабочий источник для Claude: полные данные, решения, источники, без вёрстки.
   `.html` — для человека: просмотреть, показать заказчику, задеплоить. HTML собирается
   из содержания MD и не содержит фактов, которых нет в MD. Меняется MD — пересобирается HTML.
   Человеческий HTML должен быть автономным: открываться одним файлом, картинки встроены.
   Исключения: `README.md` (индекс для GitHub) и `CLAUDE.md` (бриф).
   Человеческий индекс — `index.html` в корне: при новом этапе или артефакте обновляется вместе с README.
   HTML деплоится на Vercel (https://skinhub-topaz.vercel.app) автоматически при push в `main`;
   MD на сайт не попадают (`.vercelignore`). Сайт публичный — ничего закрытого в HTML не кладём.
2. **README.md — живой индекс.** Любое изменение в репо (новый файл, завершённый этап)
   сразу отражается в README: статус этапа и ссылка на артефакт.
3. **Решения ссылаются на исследование.** Новый принцип или паттерн указывает источник:
   конкурента, скриншот или метрику.
4. **Скриншоты** лежат в `research/screens/` и называются `<сайт>-<экран>.jpg`.
5. **Язык.** Документация на русском. Интерфейсный копирайт на английском, с русской локализацией.
6. **Цифры с источником.** Метрики конкурентов приводятся с датой и источником
   (Similarweb, Trustpilot).
